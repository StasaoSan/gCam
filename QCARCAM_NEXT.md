# QCarCam: следующий выезд к машине

Camera2 здесь не является источником камер кругового обзора. Рабочая ветка исследования:

1. Подтвердить доступ штатным `qcarcam_hidl_test` от пользователя `shell`.
2. Извлечь usage, ELF-зависимости и vendor-конфиг с реальными `inputId`, форматами и разрешениями.
3. Сравнить запуск от `shell`, `root` и домена приложения. Это отделяет ошибку ABI от SELinux/HIDL ACL.
4. Только после подтверждения кадра штатным клиентом собирать native-клиент с точными vendor-заголовками.
5. После `getFrame()` передавать импортированный аппаратный буфер в `MediaCodec`; контейнер писать через `MediaMuxer`.

## Подтверждено на Geely G636 (2026-10-03)

- HIDL: `vendor.qti.automotive.qcarcam@1.0::IQcarCamera/default`.
- Сервис: PID 408, user `system`, SELinux domain `vendor_hal_ais_qti`.
- `qcarcam_query_inputs()` возвращает 6 descriptors.
- Размер приватной структуры `qcarcam_input_t` — `0x140` байт.
- Все потоки имеют `1280x800`, UYVY `0x07080102`.

| ID | FPS | Результат |
|---:|---:|---|
| 0 | 25 | боковая физическая камера, кадры получены |
| 1 | 25 | противоположная боковая камера, кадры получены |
| 2 | 25 | продольная физическая камера, кадры получены |
| 3 | 25 | противоположная продольная камера, кадры получены |
| 12 | 25 | кадры получены; ракурс совпадает с ID 2 |
| 14 | 30 | open/start успешны, но без внешнего условия frame callback не приходит |

Штатный `qcarcam_hidl_test` успешно выполнил полный цикл `open -> s_buffers -> start ->
get_frame -> release_frame`. Первый кадр приходит примерно за 240–250 мс.

## Подключение

На Mac `adb` находится здесь:

```text
~/Library/Android/sdk/platform-tools/adb
```

Проверка подключения:

```bash
~/Library/Android/sdk/platform-tools/adb devices -l
```

Автоматический безопасный сбор (не запускает видеопоток):

```bash
./tools/qcarcam_collect.sh
```

Захват выбранного потока (нужен root-adbd или доступ к `/data/vendor/camera`):

```bash
./tools/qcarcam_capture_input.sh 0
```

Результат появится в каталоге `qcarcam-capture-YYYYMMDD-HHMMSS`. Не следует запускать
`qcarcam_hidl_test` без аргументов, пока его `-h`/строки не покажут ожидаемый конфиг: некоторые
vendor-тесты сразу захватывают камеры и могут конфликтовать со штатным AVM.

## Критерий успеха первого этапа

Нужны четыре факта: HIDL service виден; тестовый клиент проходит initialize; известен настоящий
`inputId`; штатный клиент получает хотя бы один frame callback. До этого реализация H.264/MP4
преждевременна.
